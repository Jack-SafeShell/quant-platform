# 架构与依赖方向

采用模块化单体，运行入口为 `yudao-server`，组合 system、infra、quant。根 POM 版本 `2026.08-jdk25-SNAPSHOT`、Java 25；根 Spring Boot 插件/处理器版本 4.1.0，dependencies BOM 声明 4.1.1，当前保留原样。Nacos 注册和配置默认关闭。

Vue3 → Spring Boot 应用服务 → 领域模型/风险与审批 → 引擎适配接口 → Freqtrade/Python。

- Spring Boot 是统一控制面和权威业务记录来源，负责权限、任务编排、实验记录、审批、审计和对外 API。
- MySQL 持久化业务事实；Redis 提供缓存、锁与异步协调，不作为唯一任务或审批事实来源。
- Freqtrade 是第一阶段主要回测、优化、模拟与后续执行引擎。引擎本地运行状态和订单执行事实通过适配层回传、对账；平台不能凭缓存假定成交。
- Northstar 保留为可替换引擎研究，不进入第一阶段关键路径。
- AI 通过受限研究服务读取授权数据，形成建议、草案或分析结果；必须经过平台校验，不能直接调用实盘资金操作。

## 独立领域模型

策略代码、策略版本、参数集、回测任务、回测结果、模拟账户、风控规则、审批记录分别建模，不合并成引擎配置 JSON。策略版本不可变并带内容摘要；参数集、数据快照和引擎版本共同标识实验。订单、成交、持仓及审计记录在后续阶段独立管理。

已接入 Maven 模块 `yudao-module-quant` / `yudao-module-quant-api` / `yudao-module-quant-server`，Java 包 `cn.iocoder.yudao.module.quant`，表前缀 `quant_`。当前已实现研究、回测、模拟盘准入与执行、周期遥测、告警和人工处置审计。固定风险策略以版本号和限额写入不可变就绪证据，并在运行观测中复核；完整实盘订单、成交、持仓和风控规则仍须独立建模，当前不能进入实盘。

## 适配协议

首版 `BacktestEngine` 只暴露历史回测与专属容器终止，Freqtrade 细节限于实现类。统一结果协议 schemaVersion=1，包含 totalTrades、netProfit、returnRatio、maxDrawdownRatio、时间覆盖和标准化 trades；原始引擎归档留在本机，不直接作为业务 API。当前实现与配置见 [BACKTEST](BACKTEST.md)。

定义能力查询、任务提交/查询/取消、结果读取与模拟状态接口。请求包含协议版本、任务 ID、幂等键、策略版本、参数引用、数据区间、交易模式及资源限制；结果包含统一状态、错误分类、时间、引擎版本、数据覆盖和结果摘要/产物引用。

以上为后续完整协议目标；当前提供历史回测和受控 dry-run 模拟执行，不提供实盘接口。

引擎 DTO 不得泄漏到业务领域。内部可以由适配器封装 CLI、REST 或产物文件，但上层不绑定引擎内部数据库和实现类。超时不等于任务取消，重试前必须核查原任务。成功必须同时核验数据覆盖、非空数据、预热边界与错误，不能仅依据进度 100%。

风险校验位于执行前，并在执行适配层再次校验模式、授权和限制；审批绑定具体策略、参数及风险版本，变更后失效。先建立单体内清晰边界，暂不拆微服务。
